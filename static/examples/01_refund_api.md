# Демонстрационная спецификация: возврат платежа

Синтетический пример. Не содержит клиентских данных и не относится к реальному банку.

## Функциональные требования

- **FR-01.** Владелец платежа может запросить возврат проведённого платежа, указав его идентификатор и сумму в целых тенге.
- **FR-02.** Сумма одного возврата должна быть не меньше 1 тенге и не больше остатка суммы платежа, доступного для возврата.
- **FR-03.** При успешном возврате сервис уменьшает доступный для возврата остаток на сумму возврата и создаёт запись об операции.
- **FR-04.** Повторная доставка запроса с тем же идентификатором операции возврата и теми же параметрами не изменяет остаток повторно.
- **FR-05.** При отклонении возврата остаток не меняется, сервис возвращает причину отказа.

## REST API

| Параметр | Значение |
| --- | --- |
| Description | Выполнение возврата платежа |
| **REST type** | GET |
| Request URL | `/refunds/execute` |

### Логика работы

1. Проверить принадлежность платежа клиенту.
2. Проверить идентификатор операции возврата и сумму.
3. При успешном выполнении создать запись возврата и обновить остаток платежа.
4. Вернуть результат операции.

## Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
| --- | --- | --- |
| Доступный остаток 10 000 ₸, уникальный идентификатор возврата | Запросить возврат 2 000 ₸ | Возврат выполнен, остаток 8 000 ₸ |
| Доступный остаток 1 000 ₸, уникальный идентификатор возврата | Запросить возврат 1 500 ₸ | Возврат отклонён, остаток 1 000 ₸ |
