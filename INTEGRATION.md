# REQUIRAGENTS 2.0

## Архитектура

- `web.py` обслуживает интерфейс и FastAPI. `web_engine.py` разбирает оригинальные PDF, DOCX, Markdown и TXT, сохраняет координаты и запускает анализ вне ASGI event loop. Одновременно по умолчанию обрабатывается один прогон на процесс.
- `orchestrator.py` обслуживает и FastAPI, и прежний CLI. Deep выполняет извлечение, параллельные проверки качества и согласованности, правила и контрпримеры, независимый аудит и проверку готовности. Quick использует отдельный узел и выдаёт предварительный отчёт.
- `web_report.py` проецирует результат в формат интерфейса. Полная исходная структура сохраняется в `native` при выгрузке JSON. В сводку Deep входят только подтверждённые и уточнённые замечания. Решения об отклонении и объединении присутствуют в журнале аудита. Кандидаты `REVIEW-*` отображаются отдельно и могут снизить готовность для ручной проверки.
- Three.js получает события начала, повтора и завершения узлов по NDJSON. Quick переводит персонажа от отдыха к работе при запуске своего узла. Офлайн-демо показывает сохранённые результаты, локальная проверка выполняет эвристики. Ни один сценарий не имитирует выполнение модели.
- Исправления формируют отдельный черновик. Прямая замена требует однозначной цитаты и явного предложения модели, затем подтверждения человеком. Для PDF и DOCX редактор работает с текстовым представлением, повторная проверка редакции использует новые координаты. Q&A использует локальный поиск и проверяет цитаты по тексту, а при недостатке фактов показывает неопределённость.
- Профиль из `AUDIT_PROFILE` задаёт локальные проверки, отчётные разделы и дополнительные рекомендации для Gemini. Схемы, набор этапов и проверка доказательств остаются общими. UI поддерживает ru/kk/en, исходные цитаты сохраняются, официальный PDF формируется на русском.

## Восстановление независимого аудита

Auditor проверяет замечания пакетами по 12. Значение `AUDIT_BATCH_SIZE` ограничено диапазоном 1–16. При нарушении контракта повторный запрос включает только отсутствующие или невалидные решения. Межпакетный проход рассматривает до 120 допустимых направлений объединения с общей привязкой к исходному требованию и совпадающими причиной и областью. Общая проверка затем валидирует весь собранный результат. Дубликаты без подходящей привязки или с разными формулировками причины могут сохраниться.

`GEMINI_AUDITOR_MODEL` переопределяет основную модель аудитора (`gemini-3.5-flash-lite` по умолчанию). Если задана `GEMINI_AUDITOR_RETRY_MODEL`, третья попытка в каждом пакете или межпакетном проходе начинается с неё и использует обычный fallback Gemini. При отсутствии переменной используется основная модель. Дополнительные пакеты и повторные запросы расходуют квоту. Серверный журнал указывает этап, попытку, правило и распознанный ID замечания, где это возможно.

Если аудит исчерпал попытки, Deep возвращает частичный результат без оценки готовности и с предварительными замечаниями. В браузере кнопка «Повторить только аудит» работает для исходного набора файлов и настроек. По умолчанию checkpoint хранится до 10 минут в памяти обслужившего запрос процесса, максимум четыре незавершённых прогона. После перезапуска или вытеснения запись недоступна. В режиме нескольких процессов запрос повтора должен попасть в исходный процесс. При включённом с согласия пользователем SQLite повтор с теми же входом и настройками работает и после перезапуска. CLI возвращает код 2 для частичного отчёта и сохраняет PDF и `partial_validation.json`; повтор той же команды с `--cache` продолжает аудит. Обновление движка или изменение моделей и размера пакета меняет ключ checkpoint. Уже сохранённые checkpoints предыдущей версии автоматически не восстанавливаются.

## Проверка качества

```bash
python -m unittest discover -s tests -v
node --test tests/test_auditor_frontend.cjs
python -m evaluate --check
python -m evaluate_quality
python -m evaluate_graph --check-data
python -m evaluate_graph --mode deep --output reports/graph-benchmark.json
```

Первые команды проверяют программные компоненты, подменённые ответы, сохранённые результаты Claude и структуру синтетического набора. Последняя команда выполняет новый анализ через Gemini и требует ключ, квоту и существующий каталог `reports`. Она считает совпадения с разметкой по критерию и источнику, точность, полноту, F1, ошибки, оценку критичности, долю подтверждённых цитат, покрытие извлечения, длительность, число попыток API и токены, если их вернул провайдер. Разметка не передаётся модели. Сравнение с исходными реализациями требует отдельных прогонов по общей разметке и одинаковым настройкам модели. Проценты в интерфейсе отражают модельную оценку качества требований.

## Эксплуатация и ограничения

Приложение отправляет текст в Gemini только после явного согласия. Сервер обычно удаляет временные загрузки после прогонов и держит checkpoints в памяти. С явным согласием кеш SQLite сохраняется на диске в открытом виде. Браузер хранит историю в текущей вкладке и сохраняет версии на устройстве при явной команде. Развёртывайте с TLS и управлением доступа, а `DEMO_PASSWORD` используйте только как простой общий пароль. Ограничение параллелизма действует на процесс, поэтому число процессов влияет на квоты. Закрытие соединения отменяет ожидание свободного слота, уже начатый вызов провайдера завершится со своим таймаутом. Загруженные документы считаются недоверенными данными, но инструкция модели сама по себе не исключает prompt injection. Проверяйте результат перед принятием бизнес-решений.

Сканированный PDF требует OCR до загрузки. Если часть страниц нечитаема, отчёт показывает ограничение, а модельный балл скрывается. Сцены имеют режим без анимации при ограниченном WebGL и сниженной подвижности. `analyzer.py`, `pruvia.py` и исходный набор оценки Claude сохранены для воспроизведения офлайн-демо и исторических сравнений. Основная точка входа для сдачи — `main.py`.
